# API-boundary review: native OpenCode 2.1.4

Primary reference: pinned OpenCode2.1.4 / Bun1.4.4, using its actual SDK host, provider plugin, credential resolver and SessionModelRequest. The1.18 CLI captures remain secondary regressions. The user normally uses OAuth. Earlier current-profile inspections do NOT establish the Authorization header used by a historical successful request; do not generalize those inspections into “manual OpenCode uses public access.” Public controls have an explicitly narrower diagnostic scope.

This is an audit of the pinned source and declared integration surface, not a claim about every OpenCode release, plugin, configuration, TLS endpoint or possible future API action. “All actions identical under any circumstances” cannot follow from a finite test matrix. No version, account, organization, device or session identity is fabricated to disguise differences.

## Executable evidence

`npm run test:native-api` verifies the pinned source/Bun/overlay and runs actual upstream provider, credential, model resolver and request/hook tests plus two bridge-specific same-version comparisons inside a bubblewrap network namespace. Empty private HOME, read-only source/runtime, synthetic credentials and local/fake HTTP only; no real account/profile files mounted and no external network fallback.

Result: **114 passed,0 failed**, including47 native OpenCode provider tests. The additional comparison proves common model/session headers and model/HTTP hooks match; context shaping differs deliberately. It does not pretend to be a compiled2.1 TUI capture or a live OAuth success. Existing actual1.18 lifecycle and real Claude fixtures retain their separate scope.

## Finding fixed

The prior worker keyed sessions by conversation+model, unlike native switchModel. The worker now keys by conversation, adopts an existing legacy identity, invokes host.sessions.switchModel and rejects concurrent requests on different models within the same conversation. Tests cover switch/back/restart, interrupted migration/selection without duplicate allocation, and cross-model busy protection. This changes local affinity handling; it is not a proven cause or cure for429.

## Remaining acceptance boundary

The current scheduled standalone1.18/public/Bun control is a transport diagnostic, NOT evidence of normal OAuth2.1 harness parity. No result from it should be described as a matched normal-OAuth control. A same-version authenticated live comparison still requires its own bounded preparation and exclusive credential-owner handoff. Preserve the existing one-request budget/cooldowns; do not launch an extra OAuth request to compensate for this scope correction. Live gateway/tools/reasoning/long acceptance remains incomplete.


## Terminal and diagnostic transport review

The bridge now commits executable tool calls and success/usage frames only after successful native stream exit, including finalizers. Late native failure cannot leave a successful tool-call finish visible. Text/reasoning before that point remains progressive. Chat Completions role and separate opt-in usage frames follow the declared compatibility protocol; these are caller-facing frames, not changes to provider request headers/body.

The budgeted Claude diagnostic relay remains buffered. Client disconnect now shuts down its corresponding loopback upstream socket and stops the run; malformed, embedded-error or incomplete SSE cannot count as a successful CLI result. Socket closure is verified locally, not a guarantee of remote inference termination. The relay is not evidence of untouched CLI HTTP/TLS behavior.
